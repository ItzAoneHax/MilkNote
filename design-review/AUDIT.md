## 0. 结论摘要

MilkNote 已经有明确且可识别的美感：**奶白纸面、Codex 式 mono 元数据、单强调蓝、细边界、克制的柔和阴影**。设置页的行式选择、书写页的工具互斥、框选后的深色意图条都已形成统一语言，不应推倒重来。

主要差距不在“风格不够多”，而在五类基础纪律：

1. **触控优先级不够明确**：通用 hover 上浮/淡底占据动效体系，角柄命中容差却用固定 px；撤销等单击动作还注册空双击回调。平板应首先优化按下、拖动、抬起与取消。
2. **暗色模式仍有事实性可读性故障**：诊断日志浅底浅字；系统栏未随应用主题反色；封面文字对比不足。
3. **同类浮层缺少共同尺度**：新建笔记本弹窗过宽，命令面板同样通栏；小控件与文字操作则普遍偏小。
4. **功能可发现性弱于视觉完成度**：删除笔记本、笔诊断依赖隐藏长按；Agent 空态无引导；模型管理入口名不副实。
5. **动效已有 120/140/160/180/200/220ms 基础，但没有统一语义**：页面/框选/附件为瞬切，流式列表反而持续做动画滚动，动效预算没有优先服务于触控连续性。

### 严重度定义

- **P0**：阻碍阅读或关键任务，或造成明显错误状态。
- **P1**：高频路径、暗色/适配、可发现性或可访问性存在显著问题。
- **P2**：不阻塞任务，但破坏一致性、节奏或维护性。

### 证据类型

- **[实测]**：AVD 截图或真实交互已复现。
- **[代码]**：由实现直接推出；未宣称经过真机性能/硬件验证。
- **[审美]**：基于本项目既定设计语言提出的偏好判断，并给出理由。

## 1. 设计理念还原与现有实现盘点

### 1.1 应保持的产品取舍

- **纸感优先**：工具退后、纸张是主角；书写层不能被装饰性动效或浮层拖延（`docs/DESIGN-V0.md:22-28`）。
- **Codex 骨架 + 柔和皮**：mono 只服务数字/命令/模型信息；蓝色只给 Agent 与激活态；卡片不是无投影极简（`docs/DESIGN-V0.md:167-193`）。
- **两层 IA**：书架 ↔ 书写页；侧栏只放当前笔记本页面（`docs/DESIGN-V0.md:195-232`）。
- **显式上下文**：附件由用户明确添加，不隐式上传当前页/整章（`docs/AGENT-BACKEND.md:346-377`）。
- **本地优先与可撤销**：批注贴回进入页面撤销栈，不能为视觉动效改变输入线程或落盘语义。

## 2. 逐模块问题清单

## 2.1 主题、公共组件与系统栏

### A-01 · P0 · 视觉 · 暗色诊断日志几乎不可读 **[实测+代码]**

- **现状**：日志容器使用 `onBackground.copy(alpha=0.92)`；暗色下它是浅色的 `#E8E6E0`。日志文字又固定为 `#E8E6E0/#95E6CB/#7D92FF` 等浅色。
- **问题**：浅底配浅字，默认日志实测对比约 **1.15:1**，事件内容无法可靠阅读，直接阻断 P1 笔诊断任务。
- **证据**：`app/src/main/kotlin/com/milknote/app/ui/pen/PenDiagnosticsSheet.kt:174-195`；[截图 14](screenshots/14-pen-diagnostics-dark.png)。
- **优化方向**：把“终端”定义为不随主题反转的固定深色语义组件：背景 `#14161B`，正文 `#E8E6E0`，成功 `#95E6CB`，警告 `#FFB86B`；不要复用会随主题翻转的 `onBackground` 做终端底。

### A-02 · P1 · 视觉 · 应用手动深色时系统栏仍保持浅色外观 **[实测+代码]**

- **现状**：`MilkTheme` 只替换 Compose scheme；没有在有效主题变化时同步 status/navigation bar 的底色与图标外观。
- **问题**：系统浅色 + App 深色时，状态栏黑图标落在深底上，底部导航栏则是一整条白底；书架、书写、设置均复现，破坏暗色完整性。
- **证据**：`app/src/main/kotlin/com/milknote/app/ui/theme/Theme.kt:60-77`、`app/src/main/kotlin/com/milknote/app/ui/MilkRoot.kt:78-85`；[截图 12](screenshots/12-settings-dark.png)、[截图 13](screenshots/13-writer-dark-system-light.png)、[截图 20](screenshots/20-bookshelf-dark.png)。
- **优化方向**：以最终 `dark`（不是系统值）驱动系统栏；背景与 `background` 一致，图标 `isAppearanceLight* = !dark`。书写沉浸模式再单独控制系统栏可见性。

### A-03 · P1 · 视觉 · 暗色书架用途标签使用封面原色，蓝/红对比不足 **[实测+代码]**

- **现状**：标签文字直接使用 `cover`，底色为 `cover.copy(alpha=.12)`，没有暗色前景映射。
- **问题**：实测蓝色标签难读。计算值：蓝 `#3B5BEC` 对其合成底约 **2.51:1**，红约 **3.01:1**，绿约 **3.78:1**，低于小正文 4.5:1 目标。
- **证据**：`app/src/main/kotlin/com/milknote/app/ui/bookshelf/BookshelfScreen.kt:347-358`；[截图 20](screenshots/20-bookshelf-dark.png)。
- **优化方向**：保留封面色作色点/淡底；暗色文字使用单独 `onCoverTint` 映射（如蓝 `#9DADFF`、红 `#F0958C`），逐色自动验证 ≥4.5:1。

### A-04 · P2 · 视觉 · “内投影兜底”与 elevation 语义未完全分离 **[代码+审美]**

- **现状**：`softShadow` 负责外阴影，`paintedShadow` 却在卡片/弹窗/抽屉四边内部再叠一层暗渐变。
- **问题**：它解决模拟器外阴影不渲染是合理工程兜底，但“内暗边”不是物理 elevation；用于所有层时会形成相近的脏边，而非明确的 z 轴差异。审美依据：V0 的柔和感应来自低对比与光向一致，不是每层都变暗。
- **证据**：`app/src/main/kotlin/com/milknote/app/ui/common/MilkComponents.kt:95-103,126-161`；抽屉/弹窗调用见 `AgentDrawer.kt:113-121`、`NewNotebookDialog.kt:75-84`。
- **优化方向**：保留兼容兜底，但改为按层级参数化；纸面卡片不使用四边内暗，浮层只在与内容相接的一边使用 8–12dp 遮罩渐变。真机需复核外阴影与内影是否叠加过量。

## 2.2 书架与新建笔记本

### A-05 · P2 · 视觉 · 同排新建卡与笔记本卡高度不一致 **[实测+代码]**

- **现状**：笔记本卡由 `aspectRatio(1.18)` + 文本内容决定高度；新建卡固定 `236.dp`。
- **问题**：实机同排新建卡底边明显高出一截，网格像未对齐；同时削弱了“新建”作为同类对象的可预期性。
- **证据**：`BookshelfScreen.kt:301-360,365-383`；[截图 01](screenshots/01-bookshelf-initial.png)、[截图 20](screenshots/20-bookshelf-dark.png)。
- **优化方向**：抽出同一 `NotebookCardFrame`，封面区固定相同 aspect ratio，元信息区固定 68dp；新建卡复用框架，仅替换内容。

### A-06 · P2 · 视觉 · 封面只有点阵，没有真实内容预览 **[实测+代码+审美]**

- **现状**：封面为淡彩 + `MiniDotsPaper`，笔迹示意/最新页预览未进入书架卡。
- **问题**：多个笔记本只能靠名称区分，大面积封面没有承担识别功能；与 V0“迷你纸+笔迹示意”的意图也不完全一致。
- **证据**：`BookshelfScreen.kt:310-338,386-403`；截图 01/20。
- **优化方向**：低风险方案是叠最近页的浅色缩略图；无内容时才显示点阵。不要用随机装饰笔迹伪装真实内容。

### A-07 · P1 · 功能 · 删除仅靠长按发现，笔记本也不能重命名/改封面 **[代码]**

- **现状**：卡片 `combinedClickable(onClick=打开,onLongClick=删除)`；没有可见更多入口或编辑入口。
- **问题**：新用户没有途径知道长按；创建时选错名称/封面/纸张只能删除重建。删除确认做得清楚，但入口不合理。
- **证据**：`BookshelfScreen.kt:293-307`；ViewModel 仅 `create/delete`（`BookshelfViewModel.kt:32-48`）。
- **优化方向**：卡片右上 48dp「…」→ 打开/重命名/封面与用途/导出/删除；保留长按作为熟练用户快捷方式，但绝不作为唯一入口。

### A-08 · P1 · 视觉/适配 · 新建弹窗过宽且缺少窄高窗口约束 **[实测+代码]**

- **现状**：只设水平 `120.dp` padding，没有 `widthIn(max=…)`、垂直滚动或内容分组列。
- **问题**：3:2 平板上弹窗几乎通栏，输入框极宽而色点/chips 又挤在中央，尺度关系失衡；小窗口/IME 下存在纵向溢出风险（代码推演）。
- **证据**：`NewNotebookDialog.kt:74-85`；[截图 02](screenshots/02-new-notebook-light.png)、[截图 21](screenshots/21-new-notebook-dark.png)。
- **优化方向**：`widthIn(max=600.dp).fillMaxWidth()`，内容 24dp；名称+实时封面预览在上，选项按行分组；`heightIn(max=available)` + `verticalScroll`。触控打开时请求名称焦点并按场景弹 IME；外接键盘输入只是同一表单的增强路径。

### A-09 · P1 · 视觉/可访问性 · 新建选项与全局小按钮低于统一触控目标 **[代码+实测]**

- **现状**：色点 30dp；书写工具 32dp；撤销 30dp；Agent 关闭/发送 30dp；文字操作常只有 25–35dp 高。
- **问题**：视觉图标可以小，但实际 clickable bounds 也小；笔尖虽更精确，也不应为同一操作提供更小的目标。手指、笔、无笔降级使用同一套 48dp 触控标准。
- **证据**：`NewNotebookDialog.kt:120-135`；`WriterScreen.kt:314-357,494-544`；`AgentDrawer.kt:180-188,630-655`；[截图 02](screenshots/02-new-notebook-light.png)、[截图 03](screenshots/03-writer-light.png)。
- **优化方向**：默认命中区统一至少 **48×48dp**；视觉图标仍 18–19dp。开关同时让整行可点， chips/文字按钮用透明外扩命中区；密集顶栏优先收入「更多」，不要靠缩小目标塞下。

## 2.3 书写页、页面侧栏与框选

### A-10 · P1 · 功能 · 笔状态条无条件显示“笔 就绪” **[实测+代码]**

- **现状**：无论是否探测到笔/是否连接，状态条固定写“笔 就绪”；同时笔电量为 `--%`。
- **问题**：同一屏给出互相矛盾的状态，用户无法判断无笔、未授权、蓝牙断开还是可书写。
- **证据**：`WriterScreen.kt:686-711`；`penConnected` 已在 `WriterScreen.kt:103-108` 计算但未传给 StatusBar；[截图 03](screenshots/03-writer-light.png)。
- **优化方向**：显示真实能力而非连接假设：`未检测到笔·手指可写` / `已连接·82%` / `蓝牙未连接·压感仍可用`。只在状态变化时提示，不常驻技术详情。

### A-11 · P1 · 功能 · 页面只能新增/切换，缺少删除、复制、重排序 **[代码]**

- **现状**：侧栏仅 `onSwitch/onNewPage`，无可长按菜单；命令面板也只有新建页。
- **问题**：误建空白页无法清理；课堂拆分一题一页、复制模板页等常见流程缺失。
- **证据**：`WriterScreen.kt:547-641`；`MilkRoot.kt:191-196`；`WriterViewModel.kt:285-304`。
- **优化方向**：缩略图长按/更多 → 复制页、移动、删除；删除非空页必须确认且可撤销。新增页沿用当前纸型并给 200ms 列表定位反馈。

### A-12 · P1 · 功能/动效 · 框选 FROZEN 初始态没有任何操作引导 **[实测+代码]**

- **现状**：刚进入时只有统一灰遮罩；顶部操作和意图条要等 `CONFIRMED` 才出现。
- **问题**：用户不知道下一步是拖动、如何取消；失败或误触后像“屏幕被锁住”。
- **证据**：`SnipOverlay.kt:124-136,172-244`；[截图 06](screenshots/06-snip-frozen.png)。
- **优化方向**：首次/每次 FROZEN 显示轻量居中提示「用笔或手指拖动框选」+ 至少 48dp 的可见「取消」；开始拖动立即淡出。系统 BACK 与 Esc 是辅助出口，不替代触控取消。

### A-13 · P2 · 视觉 · 选区尺寸标签会压到左上角手柄 **[实测+代码]**

- **现状**：尺寸标签根据 `r.t-30f` 定位，横向从 `r.l` 开始，未考虑标签自身高度和手柄 7dp 半径。
- **问题**：实测标签遮住左上的角柄，削弱拖点辨识。
- **证据**：`SnipOverlay.kt:138-169`；[截图 07](screenshots/07-snip-confirmed.png)。
- **优化方向**：用 `onSizeChanged` 获取标签高，默认放在选区上方 `12dp + labelHeight`；靠顶时放到选区内右上，永不覆盖四角命中区。

### A-14 · P1 · 功能 · 框选只禁用五个工具，撤销/墨色/粗细/导出仍可操作 **[代码+实测]**

- **现状**：`enabled=!snipActive` 只传给 `ToolIcon`；其余顶栏控件没有统一禁用。
- **问题**：冻结模式的语义不一致，用户可在选区期间改变将送入 Agent 的工具状态或触发导出。
- **证据**：`WriterScreen.kt:251-253,280-385`；[截图 07](screenshots/07-snip-confirmed.png) 中墨色/粗细仍呈可用态。
- **优化方向**：以统一 `chromeMode` 控制整个编辑组；只保留 Agent、取消、必要导航。视觉上 38% 不透明度和语义 disabled 同步。

### A-15 · P1 · 功能 · 文档承诺的沉浸书写没有落地 **[代码]**

- **现状**：V0 写明顶栏/侧栏可自动隐藏；当前 Writer 始终渲染顶栏、侧栏、状态条，没有沉浸状态或入口。
- **问题**：长笔记/小分屏时 chrome 始终占据空间；与“界面退后”的核心原则有差距。
- **证据**：`docs/DESIGN-V0.md:209-213,229-232`；`WriterScreen.kt:155-234`。
- **优化方向**：顶栏提供 48dp「专注」按钮，命令面板作为第二入口；退出用同样明确的触控按钮/系统 BACK。不要把双击纸面作为主路径，以免与落笔、点按和双击判定竞争。切换只动 chrome，不缩放/移动纸张坐标。

### A-16 · P1 · 功能 · 顶栏 Agent 与笔电量缺乏一致状态反馈 **[代码+实测]**

- **现状**：Agent 打开后顶栏按钮文案/样式不变；书写页电量胶囊 `onClick={}`，书架同一胶囊单击却打开设置。
- **问题**：用户无法从顶栏判断抽屉是否已开/后台是否仍在流式；同一组件在不同页单击语义不一致。
- **证据**：`WriterScreen.kt:367-384`；`BookshelfScreen.kt:226-233`；[截图 04](screenshots/04-agent-setup.png)。
- **优化方向**：Agent 打开=蓝色浅底+「收起」，流式=小型进度点；电量单击统一打开笔状态/设置，长按才进入诊断并写明入口。

## 2.4 Agent 抽屉、附件与消息

### A-17 · P1 · 功能 · “管理模型 → 设置 · Agent”并不会去设置 **[代码]**

- **现状**：该入口的 `clickable` 只调用 `onDismiss`，没有导航回调。
- **问题**：明确的导航承诺未兑现，用户被留在原抽屉。
- **证据**：`app/src/main/kotlin/com/milknote/app/ui/agent/AgentDrawer.kt:887-895`。
- **优化方向**：接入 `onOpenSettings`，并将设置选中页定位为 `agent`；返回时恢复原页/抽屉/草稿。

### A-18 · P1 · 视觉/适配 · 模型面板没有高度/宽度约束，技术说明过度占据小字层 **[实测+代码]**

- **现状**：所有 Provider/模型直接铺入 `Column`；思考档 chips 为不可滚动单行；底部展示完整 wire-format 说明。
- **问题**：多 Provider 或七档模型会横向/纵向溢出（代码推演）；当前两行模型已经让 9sp 技术说明成为视觉噪声，主操作反而弱。
- **证据**：`AgentDrawer.kt:798-895,910-929`；[截图 09](screenshots/09-agent-model-sheet.png)。
- **优化方向**：模型列表 `heightIn(max=320dp)` + 懒加载；chips `horizontalScroll` 或 `FlowRow`；说明改为「不同模型的档位含义由厂商决定」+ 详情信息图标。

### A-19 · P1 · 功能 · 空会话只有大片空白，没有下一步 **[实测+代码]**

- **现状**：无消息时 `Messages` 渲染空 `LazyColumn`，底部只有 composer。
- **问题**：首次打开不知道能“讲解本页/框选/归纳本章”；核心差异化功能被空状态隐藏。
- **证据**：`AgentDrawer.kt:263-300`；[截图 04](screenshots/04-agent-setup.png)、[截图 23](screenshots/23-agent-page-dark.png)。
- **优化方向**：空态只给 3 个真实动作：「框选讲解」「讲解本页」「归纳本章」；附一句最小上传说明。发送后 160ms 交叉淡出，不滑动纸张。

### A-20 · P1 · 动效/性能 · 流式每个文本长度变化都触发动画滚动 **[代码]**

- **现状**：`LaunchedEffect(lastText.length,message.size)` 中调用 `animateScrollToItem`；诊断流水也随每条日志动画滚动。
- **问题**：流式期间不断取消/重启滚动动画，容易造成跟手抖动并不必要地消耗主线程；这是代码层风险，本次未做真机帧率结论。
- **证据**：`AgentDrawer.kt:267-280`；`PenDiagnosticsSheet.kt:61-65`。
- **优化方向**：新消息出现可 180ms 滚动；同一条流式追加使用 `scrollToItem`/直接维持底部偏移；用户上滑后立即停止跟随，并提供「回到底部」。

### A-21 · P2 · 功能/层次 · 附件面板与 slash 列表是突兀插入，页面选择只有 ID **[实测+代码]**

- **现状**：`if(showAttach)`/`if(slashSuggestions)` 直接改变 composer 高度；页面行仅 `p0001 + 附加`。
- **问题**：输入区跳动，无视觉来源；用户不能从 ID 判断页面内容。显式附件原则正确，但选择效率可提升。
- **证据**：`AgentDrawer.kt:522-584,661-771`；[截图 08](screenshots/08-agent-attachments.png)。
- **优化方向**：附件面板 160ms expand/fade，锚定 composer；页行加 48×64dp 缩略图、页码和已附加 ✓；草稿卡用真实缩略图而非统一文档图标。

### A-22 · P2 · 视觉 · 消息列表底部预留与真实布局重复 **[代码]**

- **现状**：composer 已在消息区下方的正常 `Column` 流中，消息列表仍设 `bottom=96dp`，注释称“避免被 composer 遮挡”。
- **问题**：不存在 overlay 遮挡时仍留大空带，缩短可读区域；长对话尤其明显。
- **证据**：`AgentDrawer.kt:121-129,283-288`。
- **优化方向**：正常流布局仅保留 16–24dp 底部内容间距；若改 overlay，才按 composer 实际高度动态 padding。

### A-23 · P1 · 功能 · 发送按钮在空文字/空附件时仍保持高强调可点 **[代码]**

- **现状**：非流式时始终显示蓝色发送；点击后清空本地 `text`，由后端再决定是否可发。
- **问题**：空会话容易形成“点了没反应”；视觉上也把不可用动作误呈现为主 CTA。
- **证据**：`AgentDrawer.kt:630-655`。
- **优化方向**：`canSend = text.isNotBlank() || draftAttachments.isNotEmpty()`；不可用时灰底/弱化图标但保留 48dp 命中与 disabled 语义；流式仍在同一位置切换停止，避免触点移动。

### A-24 · P2 · 功能 · 流式光标会被 Markdown 解析器当作正文 **[代码]**

- **现状**：直接把 `" ▍"` 拼到 `msg.text` 后交给 `MarkdownLite.parse`。
- **问题**：若流尾位于代码/公式/列表标记中，光标参与解析，可能出现源码闪烁或跳动。
- **证据**：`AgentDrawer.kt:380-391`；`MarkdownLite.kt:26-49,125-178`。
- **优化方向**：光标作为消息块后的独立 UI span；代码块/公式未闭合时只稳定已提交前缀。

## 2.5 设置、命令面板与更新

### A-25 · P1 · 视觉/功能 · 命令面板过宽，触控行偏小；键盘导航也未形成增强能力 **[实测+代码]**

- **现状**：面板只有水平 90dp padding；结果行约 32–36dp 高；Enter 永远执行第一条，没有 selected 状态。
- **问题**：平板上面板横向失衡；直接点按目标偏小，外接键盘用户也无法选择第 N 条。主问题首先是触控，不是桌面快捷键。
- **证据**：`CommandPalette.kt:69-88,118-153`；[截图 05](screenshots/05-command-palette-writer.png)。
- **优化方向**：宽 `min(640dp, available-64dp)`；结果行至少 52dp，点按整行立即执行；只有检测到方向键/外接键盘时显示 selected 焦点，支持 ↑↓/Enter/Esc；过滤/空态保持高度稳定。

### A-26 · P1 · 功能 · 新增 Provider 表单没有取消路径 **[实测+代码]**

- **现状**：`AddProviderDialog` 只有 `onConfirm`，底部只有「保存」；其实现为内容列内 `DialogCard`，并非真正模态。
- **问题**：误点新增后只能保存或切走设置页；表单名与层次语义也不一致。
- **证据**：`AgentSettings.kt:131-136,674-755,783-803`；[截图 16](screenshots/16-add-provider-dark.png)。
- **优化方向**：若保留 inline 模式，标题改「新增 Provider」卡并提供「取消」；更推荐独立 560dp 模态，Esc/遮罩/取消均关闭，未保存内容有提示。

### A-27 · P1 · 功能 · Provider/模型删除没有确认或撤销 **[代码]**

- **现状**：「删除 Provider」直接 `removeProfile`；模型 ✕ 直接 `removeModel`。
- **问题**：Provider 包含端点、模型声明与调档结果，误点会丢失一套配置；危险按钮与切换/测试同一行，触控目标又小。
- **证据**：`AgentSettings.kt:98-105,218-231,525-577`。
- **优化方向**：Provider 删除确认并说明是否影响历史会话；模型删除用 5s Snackbar「已移除 · 撤销」。默认模型不可直接删，先指定替代。

### A-28 · P1 · 功能 · 缺少“减弱动效”与系统减少动画适配 **[代码]**

- **现状**：所有 tween/expand/slide 无条件执行；设置只有主题、压感、front-buffer 等。
- **问题**：对前庭敏感或偏好安静界面的用户无控制；大量 200ms 颜色动画也无法统一降级。
- **证据**：`AppSettingsStore.kt:20-26`；`MilkComponents.kt:81-198`；`SettingsScreen.kt:128-174`。
- **优化方向**：设置 → 外观「动效：跟随系统/标准/减弱」；减弱时位移/缩放归零，只保留 ≤80ms 透明度或即时状态；书写输入与悬停光标永不附加延迟。

### A-29 · P2 · 功能 · 压感曲线只有抽象 γ 说明，没有试写反馈 **[实测+代码+审美]**

- **现状**：柔和/标准/灵敏 + γ 数字；没有同一笔画的预览或诊断联动。
- **问题**：普通用户难以从 γ 判断差异；设置后需回书写页反复切换。
- **证据**：`SettingsScreen.kt:147-174`；[截图 18](screenshots/18-settings-writing-dark.png)。
- **优化方向**：行下提供静态三条「轻触—重按」宽度曲线，选中档高亮；不必做实时画布，避免把设置页变成第二个书写引擎。

### A-30 · P1 · 功能 · 更新失败/连接失败的可诊断信息不足 **[实测+代码]**

- **现状**：连接失败常只剩「连接失败」；更新失败为「连不上更新服务/下载失败(服务开着吗?)」。错误详情被截断或底层返回 `null`。
- **问题**：用户无法区分地址未保存、DNS、鉴权、协议、超时或权限；本地 Mock 实测即使地址与 Key 已填也只得到笼统失败。
- **证据**：`AgentSettings.kt:91-96`；`SettingsScreen.kt:296-364`；`AppUpdater.kt:40-55,66-93`；[截图 24](screenshots/24-provider-expanded-mock.png)。
- **优化方向**：用户层一行明确原因 + 可展开技术详情（host/HTTP/timeout，不含 Key）；保存地址后更新 dirty 状态；网络恢复可重试。

### A-31 · P2 · 视觉/维护 · 设计 token 仍被局部魔法数绕开 **[代码]**

- **现状**：主题定义了 shapes/type，但屏幕内仍大量直接使用 8/9/10/11/12/13sp、0.5/1/1.5dp border、6/8/10/12/14/16/18/20dp radius 与固定色。
- **问题**：问题不是所有尺寸都必须相同，而是“同一语义没有同一答案”：卡片/抽屉/对话框的圆角和阴影靠各自调用组合，暗色终端/封面文字已因此产生事实故障。
- **证据**：`Type.kt:15-32`、`Theme.kt:48-58`；`MilkComponents.kt:218-255`；`AgentDrawer.kt:796-929`；`SnipOverlay.kt:138-240`。
- **优化方向**：只新增语义 token，不追求数值单一：`overlayScrim`、`consoleBackground`、`onTintedCover`、`hitTouch`、`motionPress/Enter/Exit`；现有 MilkShapes 保留。

## 2.6 R2 触控复审新增问题

### A-32 · P1 · 动效/触控 · 通用界面以 hover 为反馈，但触摸按下态没有形成同等体系 **[代码]**

- **现状**：`softCard` 默认开启 hoverLift；工具、导航、页面、模型和附件广泛使用 `softHover`，而按下主要只有 `softClickable` 的 0.97 缩放，许多可点行只有 ripple。
- **问题**：手指没有 hover，触控笔悬停也不应让卡片/工具在落笔前持续浮起。当前动效预算偏向“指针经过”，不是“触点按下—拖动—抬起”。
- **证据**：`MilkComponents.kt:71-103,164-198`；`WriterScreen.kt:533-544,567-605`；`SettingsKit.kt:91-165,232-259`。
- **优化方向**：移除通用 hover 上浮/淡底；`pointerDown` 立即给 6% 背景或 0.98 按压（80ms），抬起 100ms 恢复。笔尖 hover 仅保留纸面光标、笔宽预览与必要的命中吸附提示。

### A-33 · P1 · 触控 · 框选角柄命中容差固定为 30px，高密度平板上过小 **[代码]**

- **现状**：`nearestCorner` 用 `tol=30f` 比较视口像素距离；视觉角柄半径 7dp，但实际命中容差不随 density 转换。
- **问题**：在 3200×2136、高密度目标设备上，30px 只有约 10dp 量级，远低于 48dp 触控目标；手指尤其难以抓住角柄。
- **证据**：`SnipOverlay.kt:68-103,260-282`；[截图 07](screenshots/07-snip-confirmed.png) 可见角柄本身很小。
- **优化方向**：视觉圆点仍 7dp，命中半径用 `24.dp.toPx()`；按 pointerId 锁定当前拖动，第二触点/手掌取消或忽略，角柄拖动全程无动画。

### A-34 · P1 · 触控 · 撤销/重做/导出注册空双击与长按回调 **[代码]**

- **现状**：`IconToggleButton` 使用 `combinedClickable(...,onLongClick={},onDoubleClick={})`，虽然这些动作只需要单击。
- **问题**：空回调让简单单击额外套入双击/长按手势判定，增加触控延迟与取消分支的复杂度；具体延迟数值需真机测量，不在此虚报。
- **证据**：`WriterScreen.kt:494-503`，调用点 `WriterScreen.kt:280-290,361-365`。
- **优化方向**：改为普通 `clickable`，48dp 命中区；按下即显示状态，抬起且未取消才执行。撤销/重做/导出不注册双击或长按。

### A-35 · P2 · 触控 · Agent 只有固定宽度与小关闭钮，没有手指友好的抽屉手势 **[代码]**

- **现状**：抽屉固定 360dp；关闭按钮 26dp；没有边缘拖动调宽或头部滑动关闭。
- **问题**：分屏/阅读长回答时无法调整纸张与对话比例，关闭目标也小。
- **证据**：`AgentDrawer.kt:113-120,180-188`；[截图 04](screenshots/04-agent-setup.png)。
- **优化方向**：抽屉左缘提供 48dp 宽透明拖动区，在 320/360/480dp 间连续调整；头部横向右滑可关闭，但手势仅属于抽屉，绝不侵入纸面书写区。

## 3. 动效专项盘点与判定

| 动效 | 当前规格 | 判定 |
|---|---|---|
| 按压 | 0.97，120ms | 改为按钮 0.98/80ms；卡片/纸面不缩放，优先即时底色反馈 |
| hover/颜色/工具/选中 | 多数 200ms tween | 移除通用 hover；以 pointerDown/Up 的 80–100ms 反馈替代 |
| 书架卡片 | 6dp→12dp、上移 2px，200ms | 不再上浮；按住时淡底，抬起后立即打开，管理入口保持可见 |
| 书架/侧栏列表 | `animateItem()` 默认规格 | 改成统一 180–220ms；删除避免长距离连锁位移 |
| 新建弹窗 | 默认 fade + scale | 改为统一 0.98→1 / 180ms；scrim 120ms |
| ⌘K | scrim 默认 fade；面板 180/200ms，退出 140ms | 结果行 ≥52dp、整行点按；外接键盘选中态只在键盘使用时出现 |
| Agent 抽屉 | 220ms 右滑入，200ms 右滑出 | 保留；推荐 decelerate/accelerate 曲线分离 |
| 模型面板 | 200ms expand+fade | 保留；限制高度，避免长列表撑动 |
| 设置展开 | 200ms `animateContentSize` | 保留；打开时把完整选项滚入视口 |
| 选中条/Toast | 200–220ms 滑入，140–180ms 出 | 保留；长 Toast 按文本长度调展示时长 |
| 框选进入/确认 | 无 | 加 120ms 遮罩淡入、160ms 意图条 fade+8dp 上移；选框拖动本身零动画 |
| 页面/设置导航 | 无 | 只给 chrome 120–160ms 交叉淡入；纸张不做整体滑动/缩放 |
| 流式消息 | 每长度变化 `animateScrollToItem` | 改正；流式 appended text 不动画，维持贴底偏移 |
| 附件/slash | 无 | 加 160ms expand+fade；不得反复影响已聚焦输入位置 |
| 主题切换 | 各组件状态色 200ms，但全屏颜色瞬变 | 只对 chrome 做 160ms 颜色过渡；纸面/笔迹立即切换，避免双绘开销 |

**手写铁律核验**：现有显式动画主要位于 Compose chrome，没有看到直接加到笔迹采样路径的动画；优化方案继续保持选区拖动、笔尖光标、出墨与抬笔提交零 tween。流式滚动与长列表重组应在后台/主线程预算上继续实测，本文不把 AVD 帧率当真机书写延迟证据。

### 建议自动化验收

- **截图矩阵**：亮/暗 × 系统亮/暗 × 书架/新建/书写/框选/Agent/诊断/设置五页。
- **对比度**：小正文与关键图标 ≥4.5:1；非文本控件边界/状态 ≥3:1。
- **命中区**：笔与手指共用 ≥48dp 默认目标；框选角柄半径 24dp；视觉图标不随之放大。
- **输入序列**：单击无空双击回调；pointerCancel 不执行动作；拖角柄/抽屉时第二触点被忽略；手掌不触发 UI。
- **窄高窗口**：600×840dp 与 IME 打开时，所有弹窗可滚动、CTA 可达。
- **动效**：通用组件无 hover 依赖；减弱模式无位移/缩放；框选拖动无插值；流式中用户上滑不被拉回。
- **真机补充**：Pad 8 Pro 验证阴影叠加、系统栏、抽屉/IME 与流式书写并行帧率。本次未持有笔输入与真机 GPU 数据，不作延迟结论。
